# Monetización Pro: pago, activación y control de usuarios

## Contexto

La app ya tiene el lado **cliente** completo de las licencias: claves `WLPRO-<payload>-<sig>` firmadas con HMAC-SHA256 (`license.go`), activación/desactivación en Ajustes (sección 12), paywall de Lotes/Auto-HD/Zero-Waste/Sync/Notificaciones, y botones de compra que abren `https://wakeloom.com/pro` — un dominio que **aún no existe**. Falta el lado **vendedor**: web de venta, cobro, emisión de claves y gestión de usuarios.

**Hallazgo crítico:** el secreto de firma está hardcoded y en un repo público (`license.go:17` = `wakeloom-pro-license-secret-v1-devex`). Cualquiera puede generar claves válidas hoy. Se corrige en este plan (todavía no hay usuarios, es el momento).

**Decisiones por defecto** (no respondiste la encuesta; ajustables al aprobar): Lemon Squeezy para cobro (gestiona IVA UE, checkout hospedado), **suscripción anual**, **validación online con gracia offline**, hosting en **VPS propio + GitHub Pages para la landing**.

## Arquitectura

```
Usuario → Landing (GitHub Pages, estática) → Checkout Lemon Squeezy (hosteado por LS)
LS webhook → licenseserver (Go, tu VPS) → genera clave WLPRO → email al comprador + BD
App Wakeloom → activa clave (flujo existente) + revalida online cada 24h (gracia 7 días offline)
Tú → /admin en licenseserver (token): ver usuarios, revocar, emitir manual
```

## Parte A — `licenseserver/` (nuevo paquete Go en este repo)

Nuevo dir `licenseserver/` con `package main` propio (`go build ./licenseserver`). Reutiliza el formato de clave extrayendo la lógica: crear `licensekey.go` en la raíz compartido (GenerateLicenseKey/verifyLicenseKey ya están ahí; el server los importa porque es el mismo módulo).

- **BD**: JSON en disco con mutex (mismo patrón que `libstore.go`), campos: key, email, tier, issued_at, expires_at, revoked, last_seen.
- **Endpoints**:
  - `POST /webhook/lemonsqueezy` — verifica firma HMAC del webhook (header `X-Signature` con `LS_WEBHOOK_SECRET`); en `order_created`/`subscription_created` genera clave anual (tier `pro`, `expires_at` = +1 año), la guarda y envía email; en `subscription_updated` (cancelada/expirada) marca `revoked`.
  - `POST /api/validate` — entrada `{key}`; responde `{valid, expires_at, revoked, reason}`; actualiza `last_seen`. Aquí vive la revocación real.
  - `POST /api/recover` — entrada `{email}` (rate-limit simple por IP); reenvía email con la clave si existe.
  - `GET /admin` — página mínima protegida por `ADMIN_TOKEN` (header): tabla de claves, botón revocar, formulario de emisión manual (para ventas manuales por Bizum/PayPal).
- **Email**: `net/smtp` con env `SMTP_HOST/PORT/USER/PASS/FROM`; si no hay SMTP, registra la clave en el log y queda visible en /admin.
- **Config por env**: `WL_LICENSE_SECRET` (¡el mismo que compila la app!), `LS_WEBHOOK_SECRET`, `ADMIN_TOKEN`, puerto, path de BD.
- **Tests**: firma de webhook (válida/inválida), emisión→validate→revoke→validate, recover (éxito y email inexistente), emisión manual.

## Parte C — Cambios en la app

1. **Secreto fuera del repo (crítico)**: `build_app.sh` compila con `-ldflags "-X main.licenseSecret=$WL_LICENSE_SECRET"`; en `license.go` el valor por defecto pasa a estar vacío y el build **falla** si no se define (los tests usan un secreto de test explícito). Sin cambios de formato de clave.
2. **Validación online con gracia** (`license.go` + `config.go`):
   - Nuevos campos Config: `license_last_check`, `license_valid_until` (cache), `license_api` (URL del server, default `https://lic.wakeloom.com`; vacío = solo offline, útil para el modo actual).
   - Nueva goroutine en `main.go`: al arrancar y cada 24h, si hay clave Pro y hay red, `POST /api/validate`; respuesta ok → extiende cache +7 días; `revoked`/expirada → downgrade a Free (mismo camino que deactivate); sin red → se mantiene Pro mientras `now < license_valid_until`.
   - `IsPro()` sigue siendo local y síncrona (no bloquea), solo ahora además exige cache vigente si `license_api` está configurada.
   - Tests: gracia offline, revocación, server inalcanzable (httptest).
3. **Opciones de usuario en la UI** (`ui/app.js`, `ui/index.html`, `ui/i18n.js` — ES+EN):
   - En el modal de licencia: enlace "¿Perdiste tu clave? Recuperar ↗" (a `web/recover.html`) y, si Pro, "Gestionar suscripción ↗" (URL del portal de cliente LS; nueva clave en i18n).
   - Estado sutil de verificación: "Licencia verificada hoy" / "Sin conexión: válida hasta {fecha}" bajo `#licExpiresText`.
   - `pricing_url` ya funciona; ahora tendrá destino real.
